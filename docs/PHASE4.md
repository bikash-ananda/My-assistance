# Phase 4 — Business operations

## Local business workspace

- Owner-only contacts with email, phone, organization, private notes, optional follow-up time, and archive controls.
- Sales opportunities linked to contacts with amount/currency, expected close date, six pipeline stages, and archive controls.
- Changes are audited without copying contact details into audit records. CRM data stays in SQLite and is never added to assistant prompts.

## Google connections


- Owner-only OAuth authorization-code flow with single-use state, PKCE, a ten-minute state expiry, and separate Gmail and Calendar consent.
- Read-only scopes: Gmail messages and Calendar events. The app does not send mail, create invitations, or change calendar events.
- Refresh tokens are encrypted before SQLite storage using the key generated by `scripts/setup.ps1`. Short-lived access tokens stay in request memory.
- Gmail previews return at most 25 message headers and short snippets on request. Calendar previews return at most 50 primary-calendar events for the next 14 days. These records are not copied into the Bikash AI database or sent to a model automatically.
- Disconnect removes the saved local refresh token. To remove the Google consent grant as well, revoke Bikash AI from your Google Account security settings.

## Account setup

1. Run `scripts/setup.ps1` once; it creates the private token-encryption key in `.env`.
2. In Google Cloud, enable Gmail API and Google Calendar API. Create a Web application OAuth client and configure the consent screen for your account.
3. Add this exact local redirect URI to that OAuth client: `http://localhost:3000/api/v1/integrations/google/callback`.
4. Put the client ID, client secret, and matching redirect URI in the ignored `.env` file. Never put them in `.env.example`, source code, browser settings, or the repository.
5. Start the local API and web app, sign in, open **Automation → Business connections**, and connect each service. Google consent is required before any data is read.

For an HTTPS deployment, register the exact HTTPS callback URL for the selected site and set `BIKASH_COOKIE_SECURE=true`. Keep the callback on the same origin as the web app. Review reverse-proxy access logs and redact query strings on the callback route before production; authorization codes are short-lived but sensitive.

The current Compose network is outbound-isolated. Google OAuth and API requests work only in local Windows development until an explicit server egress design is approved and reviewed.

## Data and limits

The previews are read-only and fetched only when requested. Gmail search defaults to the last seven days. Content returned by Google is external, untrusted data and must be checked before acting on it. The connection screen never receives OAuth client secrets or refresh tokens.

No Google client, consent, or connected account was supplied during development. The integration is implemented but remains disconnected until you add those values and grant consent.
